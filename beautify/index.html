코드 뷰티파이어 & 웹 뷰어

HTML, CSS, JavaScript, PowerShell 코드를 표준 들여쓰기로 즉시 정렬하고, 압축(Minify) 및 실시간 브라우저 렌더링 화면을 확인합니다.

코드 뷰티파이어 사용 방법 안내:
  1. 코드를 직접 입력하거나 [📂 파일 열기] 또는 [샘플]을 클릭합니다.
  2. 상단에서 HTML, JavaScript, CSS, PowerShell 언어 모드와 들여쓰기(2칸/4칸/탭) 옵션을 선택합니다.
  3. [⚡ 압축 (Minify)] 버튼을 누르면 주석과 불필요한 공백이 제거되며(PowerShell은 줄 구조 유지), [⛶ 전체화면]으로 새 탭에서 전체 웹페이지로 실행할 수 있습니다.
  4. 양쪽 에디터 어디든 마우스로 클릭하면 실시간 행/열 번호(Ln, Col)와 파일 크기를 즉시 확인할 수 있습니다.

코드 뷰티파이어(Beautifier)와 웹 뷰어의 실무 동작 원리

DevWorKit 코드 뷰티파이어 & 웹 뷰어는 줄바꿈과 들여쓰기가 깨진 소스 코드를 표준 코딩 컨벤션에 맞추어 깔끔하게 포맷팅하고, HTML/CSS/JS 코드가 브라우저에서 실제로 렌더링되는 화면을 실시간 샌드박스로 검증할 수 있는 개발자 툴킷입니다.

1. 토큰 기반 포맷팅과 인덴트 규칙

단순히 엔터(줄바꿈)나 공백을 무작정 삽입하는 방식은 문자열 리터럴 내부의 공백까지 훼손할 위험이 있습니다. 본 도구는 오픈소스 포맷터 js-beautify 엔진을 사용합니다. 코드를 토큰(Token) 단위로 분해해 줄바꿈과 들여쓰기만 다시 배치하므로 문자열 내부의 공백은 건드리지 않습니다.

  • 언어별 맞춤 정렬: HTML 태그의 계층 구조, CSS 룰셋 블록({}), 자바스크립트 함수 및 제어문 스코프를 따라 2칸(Space 2), 4칸(Space 4), 탭(Tab) 중 지정된 인덴트로 정확히 들여씁니다.
  • 안전한 압축(Minify): 문자열·정규식·템플릿 리터럴 내부는 건드리지 않고 주석과 불필요한 공백을 제거합니다. 줄 끝 세미콜론을 생략한 자바스크립트처럼 줄바꿈에 의존하는 코드는 오동작을 막기 위해 해당 줄바꿈을 유지하며, 절감되는 용량은 코드에 따라 다릅니다.
  • PowerShell(.ps1) 정렬: 중괄호·소괄호·해시테이블(@{}) 깊이에 맞춰 들여쓰고, if(·foreach(·}else{ 같은 키워드 주변 공백을 정리합니다. here-string(@"..."@)과 블록 주석 내부, 문자열 안의 내용은 원문 그대로 유지합니다. PowerShell은 줄바꿈이 문장 구분자라서 압축 시에도 한 줄로 합치지 않고 주석·빈 줄·들여쓰기만 제거합니다.
  • 실시간 행/열(Ln, Col) 상태 추적: 에디터 내부의 커서 위치를 실시간 모니터링하여 오류 발생 줄을 즉시 찾아낼 수 있습니다.

2. 실시간 독립 샌드박스 렌더링과 전체화면 뷰어

HTML 탭에서는 우측 상단의 [화면 미리보기] 토글을 통해 별도의 로컬 웹서버 구동 없이 브라우저 메모리상에서 iframe을 이용해 결과물을 렌더링합니다. [⛶ 전체화면] 버튼을 클릭하면 팝업 블록 없이 새 탭에서 실제 완성된 웹페이지처럼 반응형 UI를 직접 테스트할 수 있습니다.

3. 자주 묻는 질문 (FAQ)

Q. 입력한 소스 코드가 외부 서버로 전송되거나 노출될 위험이 있나요?
A. 전혀 없습니다. DevWorKit의 코드 뷰티파이어는 100% 클라이언트 사이드 자바스크립트 엔진으로 구동됩니다. 사용자의 PC 브라우저 내부에서만 연산이 수행되며 어떠한 코드 데이터도 외부 서버로 전송되지 않습니다.
Q. 프론트엔드 실무에서는 보통 2칸과 4칸 중 어떤 들여쓰기를 권장하나요?
A. 모던 웹 개발(React, Vue, Node.js 등) 및 Google, Airbnb 스타일 가이드에서는 가로 스크롤을 줄이고 가독성을 높이기 위해 2 Spaces(2칸 들여쓰기)를 사실상의 업계 표준으로 채택하고 있습니다. 백엔드(Java, C++, Python) 코드인 경우 4 Spaces를 권장합니다.
Q. PowerShell 스크립트를 정렬하고 다운로드했는데 한글이 깨져요.
A. Windows PowerShell 5.1은 BOM이 없는 UTF-8 파일을 ANSI(한국어 Windows에서는 CP949)로 읽어 한글이 깨질 수 있습니다. 이 도구는 .ps1 다운로드 시 UTF-8 BOM을 자동으로 붙여 이 문제를 막습니다. 파일을 불러올 때도 UTF-8, UTF-16(BOM), EUC-KR 인코딩을 자동으로 판별합니다. [결과 복사]로 붙여넣는 경우에는 BOM이 포함되지 않습니다.
Q. 압축했더니 코드가 동작하지 않아요.
A. 압축 결과가 이상하다면 원본 코드의 문법 오류나 브라우저 전용 문법(예: 줄 끝 세미콜론 생략 + 줄바꿈에 의존하는 표현)을 먼저 확인해 주세요. 이 도구는 문자열, 정규식, 템플릿 리터럴을 보호하며 압축하지만 난독화·변수명 단축 같은 고급 최적화는 하지 않습니다. 운영 배포용 번들에는 Terser 같은 전문 도구 사용을 권장합니다.
