웹 접근성(WCAG 2.1) 명도 대비비와 UI 배색 계층 아키텍처

DevWorKit 웹 색상 스튜디오 & UI 가독성 인스펙터는 프로덕트 디자이너와 프론트엔드 엔지니어가 디자인 시스템을 구축할 때 겪는 시각적 가독성 저하 문제를 해결하고, W3C 국제 웹 접근성 표준을 만족하는 체계적인 3채널 배색(Primary, Secondary, Background)을 수립할 수 있도록 돕는 전문 도구입니다.

1. W3C 상대 휘도(Relative Luminance) 기반 대비비 연산 공식

인간의 눈은 색상마다 인지하는 밝기가 다릅니다(녹색에 가장 민감하고 파란색에 둔감). 따라서 단순 RGB 평균값이 아닌, sRGB 감마 보정을 거친 삼색 가중치 상대 휘도($L = 0.2126R + 0.7152G + 0.0722B$)를 기반으로 명도 대비비를 산출합니다:

  • 수학 공식: $\text{Contrast Ratio} = \frac{L_1 + 0.05}{L_2 + 0.05}$ ($L_1$은 더 밝은 색상의 휘도, $L_2$는 더 어두운 색상의 휘도)
  • 일반 텍스트 기준 (AA 등급): 18pt(24px) 미만의 본문 텍스트는 최소 4.5 : 1 이상의 대비비를 유지해야 저시력자나 야외 직사광선 환경에서도 정상 판독이 보장됩니다.
  • 대형 텍스트 및 그래픽 요소: 18pt 이상 또는 14pt 볼드 텍스트, 버튼 테두리 및 입력 폼 컴포넌트는 최소 3.0 : 1 이상을 충족해야 합니다.

2. 다크모드 배색 시 순수 블랙(#000000)을 지양해야 하는 이유

많은 주니어 개발자가 다크모드를 구현할 때 배경색을 #000000, 글자색을 #FFFFFF로 극단 배색하곤 합니다. 이 경우 대비비가 21:1에 달해 OLED 화면에서 빛 번짐(할레이션 현상)과 눈의 피로도를 극대화합니다. 머티리얼 디자인(Material Design)과 애플 HIG 가이드라인에서는 진한 다크 그레이(#09090b 또는 #121212) 배경과 미세 틴트 텍스트(#f1f5f9)를 권장합니다.

3. 자주 묻는 질문 (FAQ)

Q. [⚡ 톤 최적화] 기능은 어떤 원리로 색상을 보정하나요?
A. 현재 선택된 배경색의 상대 휘도를 실시간 계산하여, 사용자가 설정한 고유 브랜드 색조(Hue)를 그대로 유지한 채 명도(Value)와 채도(Saturation)를 수학적으로 미세 조정함으로써 단 1번의 클릭으로 WCAG AA(4.5:1) 적합 기준점을 충족시키는 스마트 보정 엔진입니다.
