리눅스 크론탭(Crontab) 문법 완벽 정복과 실무 스케줄러 가이드

1. 크론탭(Cron / Crontab)의 역사와 백그라운드 스케줄링 아키텍처

크론(Cron)은 유닉스 계열 운영체제에서 특정 시간에 명령어나 쉘 스크립트를 주기적으로 자동 실행하도록 지시하는 백그라운드 데몬 프로세스(crond)입니다. 그리스 신화의 시간의 신 '크로노스(Chronos)'에서 유래되었으며, 폴 빅시(Paul Vixie)가 1987년에 재작성한 'Vixie Cron'이 오늘날 리눅스 표준 배포판(Ubuntu, CentOS, Debian, RHEL)의 사실상 표준 아키텍처로 안착했습니다.

시스템 부팅 시 백그라운드로 구동되는 crond 데몬은 매 분 00초가 될 때마다 /etc/crontab 파일과 /var/spool/cron/crontabs/ 디렉터리에 등록된 사용자별 크론 테이블을 로드하여, 현재 시각과 일치하는 패턴을 가진 명령어를 포크(fork)하여 서브프로세스로 실행합니다. 따라서 데이터베이스 백업, 로그 로테이션, SSL 인증서 갱신, 주기적 배치 작업의 심장부 역할을 담당합니다.

2. 크론탭 5대 시간 필드 구조와 파싱 규칙

표준 크론 표현식은 공백으로 구분된 5개의 시간 단위 필드로 구성되며, 각 필드는 고유한 정수 범위와 연산 규칙을 갖습니다:

* * * * * [실행할 쉘 명령어/스크립트 경로] ┬ ┬ ┬ ┬ ┬ │ │ │ │ │ │ │ │ │ └──── 요일 (0 - 6, 0=일요일, 1=월요일 ... 6=토요일) │ │ │ └───────── 월 (1 - 12) │ │ └────────────── 일 (1 - 31) │ └─────────────────── 시 (0 - 23) └──────────────────────── 분 (0 - 59)
필드 위치 시간 단위 허용 숫자 범위 지원 특수 기호
1번째 필드 분 (Minute) 0 ~ 59 *, ,, -, /
2번째 필드 시 (Hour) 0 ~ 23 *, ,, -, /
3번째 필드 일 (Day of Month) 1 ~ 31 *, ,, -, /
4번째 필드 월 (Month) 1 ~ 12 *, ,, -, /
5번째 필드 요일 (Day of Week) 0 ~ 6 (0,7: 일요일) *, ,, -, /

3. 실무에서 가장 위험한 논리 함정: 일(Day)과 요일(Week)의 OR 연산

크론탭을 처음 작성하는 주니어 엔지니어들이 가장 빈번하게 겪는 버그가 **'일' 필드와 '요일' 필드를 동시에 지정했을 때의 평가 방식**입니다. 대부분 두 조건이 모두 일치하는 교집합(AND)으로 동작할 것이라 기대하지만, Vixie Cron의 공식 명세는 논리합(OR 조건)으로 동작합니다.

  • 잘못된 기대: 0 9 15 * 1 /backup.sh 작성 시 '매월 15일이면서 동시에 월요일인 날'에만 백업이 실행될 것이라 착각함.
  • 실제 동작: '일'과 '요일' 필드가 둘 다 *가 아니므로, **'매월 15일'이거나 혹은 '매주 월요일'인 날** 두 조건 중 하나만 맞아도 무조건 오전 9시에 백업이 실행되어 예상보다 4배 이상 과도하게 작업이 트리거됩니다.
  • 실무 해결책: 특정 날짜와 요일의 교집합이 필요한 경우, 스케줄러 자체는 매주 월요일(0 9 * * 1)로 설정하고 스크립트 내부에서 [ $(date +\%d) -eq 15 ]와 같이 날짜 조건을 검증하도록 분기해야 합니다.

4. 크론탭 실행 실패 3대 원인과 트러블슈팅

터미널에서 직접 실행하면 정상 작동하는 스크립트가 크론탭에 등록하면 조용히 실패하는 대표적인 3가지 시스템 원인과 해결책입니다:

  • 환경변수(PATH) 누락: 크론 데몬은 사용자의 로그인 쉘 환경변수(~/.bashrc, ~/.zshrc, /etc/profile)를 로드하지 않고 극도로 축소된 기본 경로(/usr/bin:/bin)만 참조합니다. python3, node, docker 등의 바이너리 및 타깃 파일은 반드시 /usr/local/bin/python3와 같이 절대경로(Full Path)로 명시해야 합니다.
  • 작업 디렉터리(Current Working Directory) 불일치: 크론 작업은 기본적으로 해당 사용자의 홈 디렉터리($HOME)에서 실행됩니다. 스크립트 내부에서 상대경로로 설정 파일이나 출력 로그를 참조하고 있다면 cd /app/service && ./run.sh와 같이 사전에 실행 경로를 이동시켜야 합니다.
  • 표준 출력(stdout) 및 표준 에러(stderr) 리다이렉션 누락: 실행 로그를 파일로 남기지 않으면 실패 원인을 디버깅할 수 없습니다. >> /var/log/cron_job.log 2>&1 구문을 붙여 표준 에러(2)를 표준 출력(1) 채널로 합쳐 로그 파일에 누적 기록해야 합니다.
# 실무 프로덕션 환경 권장 크론탭 등록 표준 형식 # 1. 크론 파일 상단에 필수 환경변수 명시 SHELL=/bin/bash PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin # 2. 절대경로, 타임존 명시 및 에러 리다이렉션 로그 기록 0 4 * * * cd /data/apps/backup && /usr/bin/python3 backup.py >> /var/log/backup.log 2>&1
