폴더 구조를 엑셀 트리 문서로 변환하는 원리와 실무 활용 가이드

1. 폴더 구조 문서화가 필요한 순간

프로젝트 인수인계, 보안·감사 대응 자료 제출, 신규 입사자 온보딩 문서처럼 "어디에 어떤 파일이 있는지"를 남겨야 하는 업무는 의외로 자주 발생합니다. 폴더가 수십 개, 파일이 수백 개로 늘어나면 탐색기를 보며 이름을 손으로 옮겨 적는 방식은 누락과 들여쓰기 오류를 피하기 어렵습니다.

이런 문서는 보통 엑셀로 요구됩니다. 텍스트나 워드로 정리하면 이후 특정 폴더만 필터링하거나 파일 개수를 집계하기 어렵기 때문입니다.

2. 디렉터리 트리 데이터 구조와 평탄화 원리

파일 시스템은 폴더가 하위 폴더와 파일을 포함하는 트리(Tree) 구조입니다. 이를 엑셀의 행 목록으로 바꾸려면 트리를 깊이 우선 탐색(DFS)으로 순회하면서 각 항목을 "깊이(Level)"와 함께 한 줄씩 기록하는 평탄화(Flatten) 과정이 필요합니다.

// 중첩된 폴더 트리를 엑셀 행 목록으로 평탄화하는 재귀 함수 function flatten(node, depth = 0, rows = []) { rows.push({ level: depth, name: node.name, type: node.children ? 'folder' : 'file' }); (node.children || []).forEach(child => flatten(child, depth + 1, rows)); return rows; }

이렇게 얻은 level 값만큼 이름 앞에 들여쓰기를 적용하면 엑셀에서도 트리 형태가 시각적으로 유지됩니다.

3. ZIP 파일의 구조를 압축 해제 없이 읽는 방법

ZIP 파일 끝부분에는 내부 모든 항목의 경로, 크기, 위치가 기록된 중앙 디렉터리(Central Directory)가 있습니다. 이 목록만 읽으면 파일 본문을 풀지 않고도 전체 폴더 구조를 파악할 수 있어 대용량 압축 파일도 빠르게 처리됩니다.

  • 항목 경로를 구분자(/)로 나누면 폴더 계층을 복원할 수 있습니다.
  • 일부 ZIP은 폴더 항목을 별도로 기록하지 않으므로, 파일 경로에서 상위 폴더를 추론해 보완해야 합니다.
  • 오래된 압축 도구로 만든 ZIP은 한글 파일명을 CP949로 저장하는 경우가 있어, UTF-8 기준으로 읽으면 이름이 깨질 수 있습니다.

4. 엑셀 문서로 정리할 때의 실무 팁

  • 레벨 컬럼을 별도로 둡니다. 들여쓰기만으로 계층을 표현하면 필터링이 불가능하지만, 숫자 컬럼이 있으면 특정 깊이의 폴더만 골라 보거나 피벗으로 집계할 수 있습니다.
  • 폴더와 파일의 정렬 순서를 통일합니다. 폴더를 먼저, 파일을 나중에 나열하면 트리가 훨씬 읽기 쉬워집니다.
  • 경로 길이를 확인합니다. Windows는 기본적으로 전체 경로가 260자를 넘으면 문제가 생길 수 있어, 깊은 계층 구조는 문서에 남겨 두는 것이 도움이 됩니다.
  • 수식으로 오해받는 파일명을 주의합니다. 이름이 =, +, -, @로 시작하는 파일은 엑셀이 수식으로 해석할 수 있으므로 텍스트 서식으로 저장해야 합니다.
  • 민감한 파일명은 제출 전에 걸러냅니다. 감사 자료에는 파일명 자체가 기밀 정보인 경우가 있습니다.

5. DevWorKit 폴더 구조 엑셀 변환기 활용

폴더나 ZIP 파일을 올리면 계층 구조가 트리 형태로 들여쓰기된 엑셀(xlsx) 문서로 바로 변환됩니다. 처리는 브라우저 안에서만 이루어지므로 내부 프로젝트의 파일 구조도 외부로 전송되지 않고 안전하게 문서화할 수 있습니다.
